تصحيح جذري لمسار الموظف الإداري — دورة التصحيحات المرجعية 2026-09-13

النطاق:
1) الموظف الإداري لا يستطيع فتح «تنفيذ خطة الأداء» بعد اعتماد المدير.
2) خطة الموظف لا تظهر أحيانًا للمسؤول المباشر بعد الإرسال.
3) بعض الحسابات المفعلة لا تستطيع دخول بوابة الموظف الإداري.

المعالجة:
- توحيد قراءة الخطة من مسارين دون فقد البيانات:
  admin_employee_records (السجل المرجعي) + admin_performance (مرآة دورة الاعتماد).
- بوابة الموظف تحدث حالة الخطة سحابيًا قبل تقرير إتاحة التنفيذ.
- صفحة التنفيذ تسترجع الخطة المرجعية إذا غابت المرآة المحلية.
- صفحة الخطة تستعيد أحدث نسخة سحابية قبل العرض.
- إدارة الموظف لدى المدير/الوكيل تقرأ السجل المرجعي والمرآة وتكتب قرار الاعتماد/الإعادة في كليهما.
- تسجيل دخول الموظف يطلب دور administrative_employee صراحة، فلا يتعطل الحساب إذا كانت له أدوار أخرى في المدرسة.
- لا يتم رفض حساب صحيح بسبب user_id تاريخي في school_members بعد ثبوت المدرسة + الدور + الحالة؛ هوية جلسة PlatformCloudSession هي الهوية التشغيلية.
- لا تغيير على بيانات مدارس أخرى أو أقسام أخرى.

الملفات المعدلة فقط:
- administrative_employee_login.html
- administrative_employee_portal.html
- administrative_employee_plan.html
- administrative_employee_execution.html
- admin_employee_management.html
- supabase/functions/platform-state/index.ts

النشر:
platform-state موجود مسبقًا في .github/workflows/deploy-supabase-functions.yml ضمن on.push.paths وله خطوة deploy؛ لا يلزم تعديل Workflow جديد.

فحوص منفذة:
- فحص JavaScript لكل السكربتات الداخلية في صفحات HTML المعدلة باستخدام node --check: ناجح.
- التحقق من بقاء عزل school_id وارتباط القراءة الخادمية بالمسؤول الفعلي: محفوظ.
- لا توجد عمليات حذف/ترحيل بيانات في هذا التصحيح.

اختبار قبول مقترح بعد النشر:
A) موظف مفعّل: الدخول من رابط المدرسة -> فتح البوابة.
B) موظف يرسل خطة: تظهر للمسؤول المباشر دون إعادة رفع.
C) المسؤول يعتمد الخطة: يعاد فتح حساب الموظف -> بطاقة تنفيذ خطة الأداء تصبح متاحة.
D) الدخول إلى التنفيذ: تظهر الأهداف المعتمدة نفسها.
E) موظف تابع لوكيل لا يظهر لمدير غير مسؤول عنه والعكس.
