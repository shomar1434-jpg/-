RL18 — تحليل نتائج نافس / الحفظ السحابي حسب المدرسة

السبب الجذري:
- الصفحة كانت تبدأ كل مرة ببيانات تجريبية ثابتة داخل appData.
- لم يكن هناك أي localStorage أو platform-state أو Supabase لحفظ نتيجة البطاقة بعد التحليل.
- لذلك بعد الخروج والعودة كانت الصفحة تعيد البيانات التجريبية القديمة بدل بطاقة المدرسة.
- مراجعة Supabase أظهرت عدم وجود أي module/state سابق متعلق بـ NAFS؛ أي أن التحليلات السابقة لم تكن تُحفظ سحابيًا أصلًا.

التصحيح:
1) إضافة active_school_scope + school_isolation_guard + platform-cloud-session + platform-state-engine.
2) moduleKey مستقل: nafs_results_analysis.
3) stateKey: latest_school_analysis_v1.
4) scope = school، وبالتالي كل مدرسة مستقلة لها آخر تحليل منفصل.
5) بعد تحليل PDF وحصول البيانات، يتم الحفظ السحابي ثم إعادة القراءة للتحقق قبل اعتبار الدورة مكتملة.
6) حفظ appData + extractedPdfData لجميع المواد المكتشفة + اسم الملف + وقت الحفظ.
7) عند فتح القسم: السحابة هي المصدر الأول، ثم كاش محلي خاص بنفس school_id فقط إذا تعذر الاتصال.
8) لا يتم تحميل أي بيانات تجريبية تلقائيًا.
9) إذا لم توجد بطاقة محفوظة للمدرسة، يفتح النظام على شاشة رفع البطاقة بدل إظهار مدرسة وهمية.
10) تغيير المادة داخل البطاقة المحللة يحفظ الحالة الجديدة لنفس المدرسة.
11) زر التطبيق اليدوي يحفظ كذلك سحابيًا.
12) لا يوجد أي استخدام لكاش غير مقيد بـ school_id.
