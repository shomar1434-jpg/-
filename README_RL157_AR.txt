RL157 — تصحيح عام لوضع المتابعة الصحيح للمدير والوكيل

المشكلة:
RL155 أبقى الجلسة الحقيقية للمدير/الوكيل لكنه لم يجعل حراس الواجهة الداخلية يرون دور المستخدم المستهدف، فبعض الصفحات كانت ترى role=manager/agent وتعيد المتابع إلى واجهته الأصلية.

التصحيح:
1) الجلسة السحابية الحقيقية والتوكن يظلان للمدير/الوكيل.
2) أثناء وضع المتابعة فقط تعرض PlatformCloudSession.role()/userId() هوية العرض للمستخدم المستهدف كي تفتح واجهته وأقسامه كاملة.
3) verifyAccess()/memberships() يعيدان سياق عرض read-only للمستخدم المستهدف على جهة العميل فقط؛ لا يتم إصدار جلسة خادمية باسم المستخدم المستهدف.
4) جميع محاولات الكتابة تبقى محظورة في وضع المتابعة.
5) manager.html و agent.html لا يعرضان شريط وضع المتابعة لمجرد بقاء سياق قديم في sessionStorage؛ شريط المتابعة يظهر داخل واجهة المستخدم المستهدف.
6) التنقل الداخلي يورث سياق المتابعة إلى صفحات السجل الشامل والسجلات والأقسام.
7) التصحيح عام لجميع المدارس؛ لا يوجد school_id خاص أو استثناء لمدرسة محددة.

لا تغييرات على قاعدة البيانات أو Edge Functions أو GitHub Actions.
