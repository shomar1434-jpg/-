تصحيح موحد لبوابات تكليف الدور الكامل — 2026-09-11

السبب الذي تم التحقق منه:
1) صفحات الموجه الطلابي ورائد النشاط تستخدم المسار الطبيعي: window.onload -> showWelcomeGate()، وبعد نجاح عزل/تفويض الدور تظهر واجهة الدخول ثم لوحة القسم.
2) صفحة الموجه الصحي كانت مختلفة بعد التصحيح السابق: أضيف لها مسار دخول ثانٍ خاص بالتفويض يحاول فتح لوحة القسم مباشرة بعد تحقق غير متزامن. إذا لم يكتمل هذا المسار بالشكل المتوقع بقي كل من welcome-gate وwelcome-dashboard مخفياً، فتظهر الخلفية فقط.
3) زر «العودة إلى قسمي الرئيسي» كان يعيد المستخدم أولاً إلى return_to (غالباً مركز التكليفات) ثم ينتقل المركز إلى القسم الأصلي، وهذا يفسر الظهور المؤقت لواجهة/مسار وسيط قبل العودة.

التصحيح:
- health_advisor.html:
  إعادة استخدام بوابة الدخول الأصلية showWelcomeGate() بعد التحميل، سواء كان الدخول عادياً أو بتفويض. صلاحية التفويض لا تُمنح من الرابط؛ platform-cloud-session يبقى المسؤول عن التحقق وإخفاء الصفحة/إعادة التوجيه عند الرفض.
- platform-delegated-role-portal.js:
  زر العودة ينتقل مباشرة إلى القسم الأساسي للمستخدم حسب PlatformCloudSession.role()، مع مسح سياق التفويض وإخفاء الصفحة فوراً لمنع الوميض ثم location.replace().
- unified_workspace.js:
  رفع إصدار تحميل platform-delegated-role-portal.js إلى role-v3 لضمان تجاوز كاش المتصفح.

فحص الأقسام المشابهة:
- student_advisor.html: بوابة الدخول الأصلية موجودة وتُستدعى فعلياً عند window.onload، ودور student_advisor معرف في route guard وفي validate-delegated-role.
- activity_leader.html: نفس المسار الطبيعي موجود، ودور activity_leader معرف في route guard وفي validate-delegated-role.
- teacher.html: يستخدم بوابة دخول مشابهة، لكنه ليس حالياً وجهة «تكليف دور كامل» في قائمة الأدوار المسموح بها؛ يبقى دوره الأساسي دون تعديل.

لا يوجد SQL ولا Edge Function جديدة في هذا التصحيح، لذلك لا يلزم تعديل workflow.
