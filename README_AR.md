# RL181 — التصحيح التراكمي لمدرسة بحرة الأولى

## ما الذي تم تصحيحه؟

1. منع ظهور تكليفات محرك الجاهزية للموظف ما لم يعتمد إسنادها يدويًا.
2. تشديد عزل التكليفات حسب `school_id` و`user_id` الفعليين من الجلسة السحابية.
3. سحب الإسنادات الآلية القديمة غير المؤكدة مع إبقاء سجلها التاريخي، دون حذف البيانات.
4. إعادة مطابقة مفاتيح سجلات الوكيل القديمة مع السجلات الفعلية، ومنع فتح سجل بديل خاطئ.
5. استبدال قائمة المكلفين الأصلية في القرارات والتكليفات بقائمة ثابتة متوافقة مع الهاتف:
   - لا تومض عند تحديث بيانات المدرسة.
   - تبقى مفتوحة حتى اختيار اسم أو الضغط خارجها.
   - تعرض المنسوبين النشطين في المدرسة الحالية فقط.
   - تحفظ معرف المستخدم والبريد والدور مع القرار، وليس الاسم وحده.

## الملفات

- `decisions_assignments.html`: إصلاح قائمة المكلفين الثابتة.
- `central_task_center.html`: عزل هوية المكلف وربط سجلات الوكيل.
- `central-task-cloud-adapter.js`: تصفية التكليفات السحابية للمستخدم الفعلي.
- `school_readiness.html`: منع تحويل اقتراحات الجاهزية إلى تكليفات فعلية.
- `platform-record-catalog.js`: مرجع مفاتيح السجلات.
- `wakil-records.html`: سجل الوكيل المرجعي.
- `delegated-access-guard.js`: حارس الوصول للسجلات المفوضة.

## طريقة الرفع

انسخ الملفات السبعة إلى جذر المنصة في مستودع GitHub مع استبدال الملفات المناظرة، ثم انتظر اكتمال نشر GitHub Pages.

لا تتضمن الحزمة Migration أو Edge Function جديدة، ولذلك لا يلزم تعديل workflow الخاص بنشر Supabase.

## فحص مدرسة بحرة الأولى بعد النشر

1. افتح قسم المدير ثم القرارات والتكليفات من هاتف Android.
2. اضغط «اسم المكلف» وتأكد أن القائمة ثابتة ولا تومض.
3. اختر مستخدمًا نشطًا وتأكد أن القائمة تغلق وأن الاسم يثبت في القرار.
4. افتح حساب الموظف الإداري وتأكد ألا تظهر له إلا التكليفات المسندة يدويًا إليه.
5. افتح تكليف سجل وكيل وتأكد أنه يفتح السجل المطابق ولا يفتح سجلًا بديلًا.

## ضمانات المحافظة على البيانات

- لا تحذف الحزمة قرارات أو سجلات أو ملفات سابقة.
- الإسنادات الآلية الخاطئة تتحول إلى حالة «مسحوب» للاحتفاظ بأثر المراجعة.
- القرارات التاريخية التي تخص مستخدمًا لم يعد نشطًا تبقى قابلة للقراءة، ولا يُسمح باستعمال اسمه لإنشاء قرار جديد.
