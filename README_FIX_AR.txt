تصحيح الحساب الواحد المرتبط بمدرستين مستقلتين (ابتدائية + روضة)

الملفات المعدلة:
1) school-login.html
2) supabase/functions/platform-session/index.ts

القاعدة الجديدة:
- school_id القادم من رابط المدرسة هو السياق الحاكم للدخول.
- يتم إثبات بيانات الاعتماد للحساب ثم اعتماد school_members الفعالة داخل المدرسة المحددة فقط.
- لا يتم حذف أو دمج أي مدرسة أو عضوية.
- نجاح platform-session يجعل عضوية المدرسة الفعالة مرجع حالة الحساب للواجهة، فلا يسقط الدخول بسبب users.active قديم/غير متسق.
- لم يتم تغيير manager.html أو platform-cloud-session.js، وبذلك يبقى تصحيح ثبات الدخول السابق محفوظاً.
- تجديد الجلسة يبقى محصوراً في نفس school_id + role، والجلسة البديلة تُنشأ قبل إلغاء القديمة.

GitHub Actions:
platform-session موجودة مسبقاً في workflow المركزي ضمن paths وخطوة deploy، لذلك لم تتم إضافة workflow جديد.
