تصحيح عام لخروج مدير/مديرة المدرسة مباشرة بعد فتح واجهة المدير

السبب البنيوي:
بوابة manager.html تتحقق عبر PlatformCloudSession.verifyAccess(['manager']). بعض المدارس المستقلة القديمة قد تكون عضوية المدير محفوظة بتسمية تاريخية مثل principal أو school_manager أو «مدير المدرسة»، بينما جلسة المنصة تحمل manager أو تسمية مكافئة. التحقق السابق كان يقارن نص الدور حرفيًا، فيرفض عضوية صحيحة لنفس المدرسة ونفس المستخدم ثم يمسح جلسة التبويب ويعيد المستخدم إلى صفحة الدخول.

التصحيح:
- platform-cloud-session.js: توحيد عائلة الدور عند التحقق النهائي مع بقاء schoolId وuserId شرطين إلزاميين.
- supabase/functions/platform-session/index.ts: نفس التوافق عند تجديد الجلسة والتبديل واختيار الدور عند تسجيل الدخول.
- لا حذف أو تعديل لأي بيانات مدرسة أو حساب.
- لا يسمح لمدير مدرسة بمدرسة أخرى لأن school_id وuser_id لا يزالان يتحققان بصورة مستقلة.
- platform-session موجود مسبقًا داخل .github/workflows/deploy-supabase-functions.yml ضمن on.push.paths وخطوة النشر، لذلك لا يلزم تعديل workflow.
