# RL170 — تحويل سجلات المدير والوكيل إلى سجلات تفاعلية مكتملة

## نطاق المراجعة

- سجلات المدير: 19 سجلًا، 35 صفحة نموذج.
- سجلات الوكيل: 50 سجلًا، 68 صفحة نموذج.
- مجموع عناصر الإدخال الأصلية المفحوصة: 8,700 عنصر.
- جميع عناصر الإدخال الأصلية تحمل مفاتيح حفظ، ولا يوجد عنصر إدخال ظاهر خارج الجمع والحفظ.

## التصحيحات المنفذة

1. إضافة محرك موحد يراجع كل سجل بعد عرضه ويحوّل مواضع التعبئة الجامدة إلى `input` أو `textarea` أو `select` بحسب معنى الخانة.
2. معالجة الخانات المنقولة كنص ثابت، ومنها: الاسم، المؤهل، سنوات الخدمة، المادة، التخصص، الوظيفة، المرحلة، الصف، الفصل، الشعبة، المسار، الهوية، البريد، الجوال، الملاحظات والتوصيات.
3. تحويل الاختيارات المطبوعة مثل «نعم/لا»، «موافق/غير موافق»، «منفذ/غير منفذ» و«إصدار/تعديل/إلغاء» إلى قوائم اختيار حقيقية.
4. إعطاء كل حقل مولد مفتاحًا ثابتًا مرتبطًا بالسجل والصف والعمود حتى يدخل ضمن المسودة والحفظ والاستعادة والأرشيف.
5. تمرير حقول الأسماء تلقائيًا إلى مركز المعلومات، مع تمييز أسماء الطلاب/الطالبات والمعلمين/المعلمات وبقية منسوبي المدرسة.
6. تعبئة البيانات التابعة عند اختيار الاسم: المسمى الوظيفي، التخصص، البريد والجوال للموظف؛ والهوية/الرقم الطلابي والمرحلة والصف والشعبة والمسار للطالب/الطالبة عند توفرها في مركز المعلومات.
7. الإبقاء على مزامنة التاريخ واليوم الحالية، مع تحويل التواريخ المطبوعة كفراغات إلى حقول متزامنة.
8. الحفاظ على بنية الطباعة والحفظ السحابي وعزل المدرسة؛ لا توجد عمليات حذف أو ترحيل لبيانات محفوظة.

## الملفات المطلوبة

- `manager_records.html`
- `wakil-records.html`
- `records-interactivity-engine.js`
- `school-information-source.js`

لا يحتاج التصحيح إلى SQL أو Edge Function أو تعديل Workflow.

## فحص الاستخدام بعد النشر

1. افتح عدة سجلات من كل تصنيف للوكيل وسجلات المدير.
2. تأكد أن الخانات النصية داخل الجداول قابلة للكتابة.
3. اضغط خانة اسم وتأكد من ظهور قائمة مركز المعلومات وثباتها حتى الاختيار.
4. اختر اسمًا وتأكد من تعبئة البيانات التابعة المتاحة.
5. احفظ، أعد فتح السجل، ثم استعده من الأرشيف.
6. اطبع السجل أو احفظه PDF وتأكد من بقاء التنسيق الرسمي.
