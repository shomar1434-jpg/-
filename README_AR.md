# RL180 — تصحيح تكليفات الموظف الإداري وسجلات الوكيل

## المشكلات المصححة

1. منع محرك الجاهزية من إرسال اقتراحات المسمى الوظيفي إلى مركز تكليفات المستخدم كتكليفات فعلية.
2. لا ينشأ تكليف جاهزية سحابي إلا عند إسناده يدويًا وصراحةً إلى المستخدم.
3. سحب تكليفات الجاهزية القديمة غير المؤكدة يدويًا، مع الاحتفاظ بالسجل التاريخي وعدم حذف الأعمال.
4. حصر عرض التكليفات على التطابق الدقيق بين `school_id` و`user_id` القادمين من الجلسة السحابية الموثقة.
5. منع معلمات الرابط أو البريد المشترك من فتح تكليف يخص مستخدمًا آخر.
6. جعل قاموس سجلات الوكيل يقرأ النماذج الفعلية الموجودة في `wakil-records.html` بدل القوائم القديمة.
7. دعم عدد من روابط التكليف القديمة وتحويلها إلى معرفات النماذج الفعلية، وعدم فتح سجل بديل عند تعذر المطابقة.

## حماية البيانات

- لا تحذف الحزمة سجلات الوكيل أو أرشيفها.
- لا تحذف التكليفات السابقة أو شواهدها.
- التكليف غير المؤكد يُسحب مع بقاء أثره التاريخي.
- لا تنقل بيانات بين المدارس أو المستخدمين.

## طريقة الرفع

ارفع الملفات الستة إلى جذر المستودع مع استبدال الملفات المناظرة، ثم انتظر اكتمال نشر GitHub Pages. لا توجد Edge Function أو Migration جديدة، لذلك لا يحتاج ملف Workflow إلى تعديل.

## اختبار القبول

1. ادخل بحساب الموظف الإداري في مدرسة بحرة الأولى وافتح مركز تكليفاتي.
2. يجب ألا تظهر مهام الجاهزية المقترحة آليًا أو سجلات وكيل لم تُسند إليه يدويًا.
3. أسند مهمة جاهزية يدويًا للموظف؛ يجب أن تظهر له هذه المهمة وحدها.
4. اسحب الإسناد؛ يجب أن تختفي من التكليفات النشطة مع بقاء أثرها التاريخي.
5. ادخل بحساب الوكيل وافتح سجلاته؛ يجب أن تظهر سجلات نوع الوكالة المرتبط بحسابه.
6. أنشئ تكليفًا بسجل وكيل فعلي وافتحه من حساب المكلف؛ يجب فتح السجل المحدد نفسه دون التحويل إلى سجل آخر.
