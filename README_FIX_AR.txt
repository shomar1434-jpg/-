تصحيح جذري لحلقة خروج مديرة المدرسة — RL140

المشكلة المتبقية لم تكن تسمية الدور فقط. وجد مساران يسببان إعادة المستخدم لصفحة الدخول:
1) بوابة manager.html كانت تنفذ verifyAccess قبل استعادة/تجديد الجلسة، ثم تمسح جلسة التبويب عند أول فشل؛ وهذا يحول فشل الاستعادة المؤقت إلى حلقة خروج.
2) platform-session قد يثبت الهوية بالبريد وكلمة المرور عبر Supabase Auth، لكنه يحتفظ أحياناً بمعرف users تاريخي/غير صالح بدل UUID الموثق أو user_id الفعال للعضوية.

التصحيح:
- استعادة/تجديد الجلسة قبل verifyAccess في كل صفحة محمية.
- بوابة المدير لا تمسح جلسة قابلة للاستعادة عند فشل تحقق واحد.
- استخدام UUID موثق من Supabase Auth أو user_id الفعال من school_members عند تطابق البريد والمدرسة.
- استعادة البريد الموثق من Auth عند غياب users row المطابق للـ UUID الحالي.
- لا يوجد تجاوز لعزل المدارس؛ school_id وتطابق الهوية/البريد الموثق يبقيان إلزاميين.
