RL11 — الانضباط الوظيفي: مراجعة المسار من البداية للنهاية

سبب العطل الجذري:
- الواجهة أزالت نموذج staffModal/staffForm اليدوي، لكن JavaScript بقي ينفذ:
  document.getElementById('staffForm').onsubmit = ...
- staffForm غير موجود في DOM، فتحدث TypeError أثناء تحميل الصفحة.
- الخطأ يوقف بقية تهيئة القسم قبل ربط حدث submit الخاص بـ recordForm وقبل boot cloud/renderAll.
- نتيجة ذلك: زر حفظ الحركة يعود لسلوك form الافتراضي ويعيد تحميل الصفحة، ولا تعمل دورة التحميل/الرسم/الإحصاءات كما ينبغي.

التصحيح:
1) حماية جميع مراجع نموذج المنسوبين القديم وعدم السماح لها بإيقاف تهيئة الصفحة.
2) ربط recordForm بحدث submit آمن صريح + preventDefault + stopPropagation.
3) إضافة type=submit وحماية form/submit من platform-page-navigation.
4) تحديث المنسوبين من School Information Center في كل boot بعد تحميل الحالة السحابية، وليس فقط عندما تكون القائمة فارغة.
5) لا تظهر رسالة نجاح حفظ المنسوبين إلا بعد تأكيد platform-discipline save؛ وإذا فشل السحاب يبقى المحلي مع تنبيه واضح.
6) persistLocal لا يسمح لخطأ localStorage quota بإيقاف الحفظ السحابي؛ يستخدم snapshot مخففًا عند الحاجة.
7) بعد حفظ الحركة: upsert_movement ثم save state ثم تحقق من وجود الحركة في state ثم تحديث السجل + لوحة اليوم + الإحصائية.
8) نفس التصحيح طبق على staff_discipline.html و wakil_staff_discipline.html لأنهما مرتبطان بنفس دورة الانضباط.

Regression Lock:
- لا تعديل على manager.html أو teacher.html أو school_information_center.html أو decisions_assignments.html.
- لا تغيير في school_id أو مفاتيح العزل الحالية.
- لا حذف لبيانات مدارس مستقلة أو حركات قديمة.
- لا حذف للسجلات المحلية عند فشل السحابة.

QA:
- JavaScript syntax errors: 0 في الملفين.
- Direct DOM references to missing IDs: 0 بعد التصحيح.
- recordForm محمي من default navigation.
- staffForm legacy أصبح اختياريًا ولا يوقف التهيئة.
- no redirect from movement save path.
